# Настройка Row Level Security (RLS) для публичного доступа к данным

## Важно!
Для корректной работы системы бронирования необходимо настроить политики Row Level Security в Supabase.

## Инструкция по настройке

### 1. Откройте Supabase Dashboard
Перейдите в раздел **SQL Editor** вашего проекта Supabase.

### 2. Выполните следующий SQL-скрипт

```sql
-- Включаем RLS для таблицы kv_store_9af35e1f
ALTER TABLE kv_store_9af35e1f ENABLE ROW LEVEL SECURITY;

-- Создаем политику для публичного чтения всех данных
CREATE POLICY "Public read access for all users"
ON kv_store_9af35e1f
FOR SELECT
USING (true);

-- Проверяем, что политика создана
SELECT * FROM pg_policies WHERE tablename = 'kv_store_9af35e1f';
```

### 3. Проверка настройки

После выполнения SQL-скрипта:

1. **Перезагрузите главную страницу** (не админку!)
2. Откройте в **режиме инкогнито** или на **другом устройстве**
3. Проверьте, что:
   - Услуги отображаются корректно
   - Мастера загружаются
   - Товары в магазине видны
   - Слоты времени доступны

### 4. Что делает эта настройка?

- **ENABLE ROW LEVEL SECURITY** - активирует систему безопасности на уровне строк
- **CREATE POLICY "Public read access"** - разрешает всем пользователям читать данные (SELECT)
- **USING (true)** - означает, что политика применяется ко всем строкам без ограничений

### 5. Безопасность

Эта политика безопасна, так как:
- Разрешено только **чтение (SELECT)** данных
- **Изменение данных (INSERT, UPDATE, DELETE)** по-прежнему требует авторизации через admin token
- Публичный доступ получают только опубликованные данные

## Проверка работы

1. Откройте главную страницу в режиме инкогнито
2. Нажмите "Выбрать услугу"
3. Должны отобразиться все опубликованные услуги

### Тест 2: Проверка мастеров
1. Откройте главную страницу
2. Нажмите "Выбрать мастера"
3. Должны отобразиться все активные мастера

### Тест 3: Проверка товаров
1. Нажмите кнопку "Магазин"
2. Должны отобразиться все товары в наличии

## Часто задаваемые вопросы

**Q: Нужно ли настраивать RLS для каждой таблицы?**
A: Нет, в этом проекте используется одна таблица `kv_store_9af35e1f` для всех данных (KV хранилище).

**Q: Могут ли пользователи изменять данные?**
A: Нет, политика разрешает только чтение. Изменение данных доступно только через админ-панель с токеном авторизации.

**Q: Что если данные не отображаются после настройки?**
A: Проверьте:
1. Политика создана корректно (выполните SELECT из шага 2)
2. В админ-панели опубликованы данные
3. Очистите кэш браузера
